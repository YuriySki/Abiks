# 00. Глоссарий

Термины в том значении, в каком их использует пособие. В скобках — глава, где термин вводится или раскрывается.

| Термин | Значение |
|---|---|
| **Агент** | Управляемая единица работы: получает цель, собирает контекст, использует инструменты, производит результат и знает, когда остановиться. Рассматривается как должность, разобранная до исполнимой функции (гл. 3). |
| **Функция** | Узкая зона ответственности с одним основным результатом, под которую проектируется агент; противоположность «универсальному агенту по маркетингу» (гл. 3, 6). |
| **Паспорт агента** | Единое описание агента: цель, пользователь, вход, метод, инструменты, результат, качество, ограничения, эксплуатация (гл. 3, приложение). |
| **Исполнимый стандарт** | Описание задачи, по которому её можно выполнить: входные данные, порядок проверки, допустимые источники, критерии результата, правило эскалации (гл. 2). |
| **Стандарт результата** | Контракт агента с бизнесом о том, что он обязан вернуть: структура, обязательные поля, объём, ссылки на источники, уровень уверенности, правила для неизвестных данных (гл. 10). |
| **Корпоративный датасет** | Управляемая модель бизнеса, из которой агент получает факты, правила, методы и примеры; не архив файлов (гл. 7). |
| **Слои датасета** | Факты (описания продукта), правила (регламенты), методы, примеры (кейсы), ограничения, история решений (гл. 7). |
| **Источник истины** | Единственное место хранения факта (например, цены), откуда его получают все агенты через поиск или интеграцию (гл. 9). |
| **Метод трёх слоёв** | Документ показывает заявленный процесс, наблюдение — фактический, разбор исключений — настоящую систему решений (гл. 8). |
| **Владелец процесса** | Человек, имеющий право утвердить правило и принять результат; разрешает противоречия между правилами (гл. 1, 8). |
| **Зрелость (агентная)** | Способность функции быстро получить достоверные данные, восстановить ход решения и повторить процесс; пять уровней, оценивается по функциям (гл. 4). |
| **Диагностика** | Прохождение задачи вместе с исполнителем; результат — карта операций, данных и решений (гл. 5). |
| **Красные зоны** | Области, где действие агента требует человеческого подтверждения: деньги, персональные данные, юридические обязательства, здоровье и безопасность, кадровые решения, публичные заявления, необратимые операции (гл. 6, 20). |
| **MVP / пилот** | Запуск одной функции на реальных задачах параллельно с сотрудником для доказательства повторяемой деловой ценности (гл. 11). |
| **Эталонный набор** | Набор заданий и ожидаемых признаков результата для тестирования агента; пополняется каждым исправлением (гл. 11, 12). |
| **Классификация ошибок** | Ошибка данных, правила, рассуждения, интеграции; у каждой свой способ лечения (гл. 12). |
| **Человек в контуре** | Распределение ответственности по стоимости ошибки: контроль до действия, после действия или по выборке (гл. 13). |
| **Матрица автономности** | Низкий риск и высокая обратимость — автоматическое действие; высокий риск, персональные данные, деньги, необратимость — подтверждение (гл. 13). |
| **Лестница автономии** | Совет → черновик → действие с подтверждением → автодействие → контроль выборки (схема гл. 13). |
| **Безопасная лестница** | Прочитать → проанализировать → подготовить → запросить подтверждение → выполнить → записать в журнал (гл. 9). |
| **Контракт между агентами** | Договорённость о передаче работы: схема данных, обязательные поля, статусы, версия источников, уверенность, ошибки, правило повторного запуска (гл. 15). |
| **Минимальный пакет** | Содержимое передачи между агентами: идентификатор задачи, цель, входные факты, выполненные проверки, результат, источники, ограничения, следующий шаг, статус (гл. 15). |
| **Оркестратор** | Компонент, который получает задачу, определяет маршрут, вызывает специалистов, контролирует готовность, обрабатывает сбои и собирает результат; на раннем этапе — обычный процесс автоматизации (гл. 16). |
| **Workflow** | Детерминированная последовательность с заранее известными шагами; предпочтительнее свободной координации, когда маршрут известен (гл. 16, 17). |
| **Архитектуры** | Цепочка (последовательная), параллель, иерархия, исполнитель + критик, гибрид (гл. 17). |
| **Интеграции** | «Руки агента»: доступ к системам через API и MCP для чтения документов, обновления CRM, создания задач и подобного (гл. 18). |
| **Лестница подключения** | Файлы и поиск → чтение систем → создание черновиков → запись с подтверждением → ограниченные автодействия → межсистемные процессы (гл. 18). |
| **Полная стоимость** | Проектирование + данные + интеграции + лицензии + вычисления + контроль + обновления + разбор инцидентов (гл. 19). |
| **Журнал** | Запись входа, источников, вызванных инструментов, решений, подтверждений и итога каждого выполнения (гл. 16, 20). |
| **Наблюдаемость** | Картина процесса в целом: объём, успех, время, стоимость, ошибки по типам, эскалации, ручные исправления, версии данных и инструкций (гл. 21). |
| **Дрейф** | Постепенная потеря точности из-за изменения источников, рынка и способа использования агента (гл. 21). |
| **Функция усиления** | Режим внедрения, при котором агент снимает поиск, сбор и черновую работу, а специалист сохраняет профессиональное решение (гл. 23). |
| **Реестр агентов** | Перечень всех агентов с паспортами, владельцами, версиями и метриками; элемент ядра AI1 Stack (гл. 24, 26). |
| **Операционный слой (цифровой)** | Конечная ступень масштабирования: межфункциональная система агентов с едиными контрактами, доступами и наблюдаемостью (гл. 24). |
| **AI1 Stack** | Управленческая карта агентной компании: от датасета и агентов первичной подготовки до маркетинга, продаж, управления и контроля; показывает зависимости между ролями (гл. 26). |
| **Компания, понятная машинам** | Компания, которая умеет объяснить, что считает фактом, как принимает повторяющиеся решения, какой результат признаёт хорошим и кто отвечает за исключение (гл. 27). |
