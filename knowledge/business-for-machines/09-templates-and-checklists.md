# 09. Шаблоны и чек-листы

Готовые к заполнению формы из книги (главы 3, 5, 11, 15, 25 и приложения).

## T-1. Паспорт агента
Заполняется до разработки (R-03.2) и обновляется при каждой версии (R-24.1).

| № | Поле | Что зафиксировать |
|---|---|---|
| 1 | Деловая цель | Какой измеримый результат функции должен улучшиться? |
| 2 | Пользователь | Кто ставит задачу, проверяет и использует результат? |
| 3 | Вход | Какие данные обязательны до запуска? |
| 4 | Метод | Какая последовательность проверок и решений используется? |
| 5 | Инструменты | Какие системы агент читает и где может действовать? |
| 6 | Результат | Структура, поля, объём, источники, статус |
| 7 | Качество | Как измеряется пригодность и какие ошибки критичны? |
| 8 | Ограничения | Когда агент обязан остановиться и позвать человека? |
| 9 | Эксплуатация | Владелец, обновление данных, версии, журнал, резервный сценарий |

Краткая форма из главы 3: название функции; деловая цель; входные данные; методы; инструменты; права; формат результата; критерии качества; ограничения; условия передачи человеку.

## T-2. Матрица выбора первого агента
Оцените каждого кандидата от 1 до 5 по восьми критериям (R-06.3). Высокая итоговая оценка не отменяет красных зон (R-20.4): необратимые действия и высокая стоимость ошибки требуют отдельного контура контроля.

| Критерий | Вопрос | Оценка 1–5 |
|---|---|---|
| Влияние | Связь с выручкой, затратами, риском или клиентским опытом | |
| Частота | Сколько раз задача повторяется за месяц | |
| Стандарт | Насколько ясно описан хороший результат | |
| Данные | Доступность, качество и актуальность источников | |
| Измеримость | Есть ли метрика до внедрения | |
| Интеграции | Можно ли начать без сложного контура | |
| Обратимость | Можно ли отменить ошибочное действие | |
| Принятие | Готов ли владелец процесса участвовать в пилоте | |

## T-3. Контрольная карта внедрения
Десять проверок от диагностики до масштаба.

| № | Этап | Критерий выполнения |
|---|---|---|
| 01 | Диагностика | Процесс пройден на реальных примерах; потери измерены |
| 02 | Приоритет | Выбран один сценарий с эффектом, готовностью и ограниченным риском |
| 03 | Данные | Определены источники истины, владельцы и обновление |
| 04 | Паспорт | Зафиксированы функция, метод, результат, права и ограничения |
| 05 | Тесты | Создан набор обычных, крайних и конфликтных случаев |
| 06 | Пилот | Агент работает параллельно с человеком на реальных задачах |
| 07 | Экономика | Подтверждены эффект и полная стоимость |
| 08 | Эксплуатация | Назначены владелец, мониторинг, версии и аварийный сценарий |
| 09 | Связка | Результат первого агента становится входом следующего |
| 10 | Масштаб | Используются единые контракты, доступы и наблюдаемость |

## T-4. Минимальный пакет передачи между агентами
Содержимое передачи работы (R-15.3):
1. Идентификатор задачи
2. Цель
3. Входные факты
4. Выполненные проверки
5. Результат
6. Источники
7. Ограничения
8. Следующий шаг
9. Статус

Сам контракт дополнительно фиксирует: схему данных, обязательные поля, статусы, версию источников, уверенность, ошибки, правило повторного запуска (R-15.2).

## T-5. Четыре универсальных шага («Что сделать в компании»)
Книга повторяет их после каждой главы; применимы к любой функции-кандидату.
1. Выберите один реальный процесс и соберите три последних примера его выполнения.
2. Зафиксируйте вход, решение, используемые источники, исключения и формат результата.
3. Назначьте владельца, который имеет право утвердить правило и принять результат.
4. Определите одну метрику, по которой изменение будет видно в работе, а не в презентации.

## T-6. Три вопроса руководителю
Книга чередует их по главам; задавайте все три при разборе любой функции.
1. Какая часть решения основана на факте, какая — на правиле, а какая — на профессиональном суждении?
2. Как мы узнаем, что результат принят, и кто отвечает за исключение?
3. Если убрать объяснения опытного сотрудника, сможет ли новый человек повторить этот процесс?
