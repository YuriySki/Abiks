# 04. Основание: датасет, извлечение знаний, доступы, стандарт результата

Главы 7–10. Часть III «Основание».

## Глава 7. Корпоративный датасет

Схема главы (слои): Факты → Правила → Методы → Примеры → Ограничения.

### R-07.1. Датасет — управляемая модель бизнеса, а не архив файлов
- **Правило.** Датасет отвечает на три вопроса: что является истиной; кто обновляет данные; где проходит граница доступа.
- **Почему.** Архив даёт агенту файлы; модель бизнеса даёт факты, правила, методы и примеры, из которых можно принять решение.

### R-07.2. Пять слоёв датасета и история решений
| Слой | На какой вопрос отвечает |
|---|---|
| Описания продукта (факты) | Что мы продаём |
| Регламенты (правила) | Как работаем |
| Кейсы (примеры) | Что считаем хорошим результатом |
| Ограничения | Чего делать нельзя |
| История решений | Почему правило появилось |
- **Правило.** Без любого из слоёв агент начинает достраивать картину сам.

### R-07.3. Датасет проектируется от функций агентов
- **Правило.** Не собирайте всё подряд: для каждого агента определите, какие данные нужны его функции.
- **Пример.** Агент квалификации лидов: сегменты, критерии, продуктовые ограничения, цены, сценарии разговора, правила передачи. Финансовые документы, не влияющие на решение, только засорят контекст.

### R-07.4. Критерий готовности фрагмента данных
- **Правило.** Для каждого фрагмента известны: источник; владелец; дата обновления; область применения; уровень доступа.
- **Как применить.** Фрагмент без любого из пяти атрибутов не допускается в контекст агента.

## Глава 8. Как извлекать знания из компании

Схема главы: Документы → Наблюдение → Кейсы → Исключения → Правило.

### R-08.1. Сбор знаний — расследование, а не чтение регламентов
- **Правило.** Документы дают версию, наблюдение — факты, интервью — причины. Самое ценное проявляется, когда специалист объясняет, почему в одном случае следует правилу, а в другом делает исключение.

### R-08.2. Разбирать последние пять случаев, а не «работу вообще»
- **Правило.** Просите специалиста разобрать пять последних реальных случаев по вопросам: Что пришло на вход? Что проверил первым? Где сомневался? К кому обратился? По какому признаку понял, что результат готов?
- **Почему.** Конкретные эпизоды извлекают рабочие эвристики лучше абстрактных вопросов.

### R-08.3. Противоречия не сглаживать — это управленческое решение
- **Правило.** Если два руководителя называют разные правила (например, скидки), владелец процесса обязан выбрать одно. До этого агент не получает искусственную определённость.
- **Почему.** Тихое сглаживание переносит конфликт правил внутрь агента, где его невозможно увидеть и исправить.

### R-08.4. Метод трёх слоёв
- Документ показывает заявленный процесс.
- Наблюдение показывает фактический процесс.
- Разбор исключений показывает настоящую систему решений.
- **Как применить.** Правило считается извлечённым, когда все три слоя сопоставлены, а расхождения разрешены владельцем (R-08.3).

## Глава 9. Архитектура знаний и доступов

Схема главы (безопасная лестница): Чтение → Анализ → Черновик → Подтверждение → Действие → Журнал.

### R-09.1. Один документ — разные доступы для разных агентов
- **Правило.** Доступ к документу определяется функцией агента, а не самим документом.
- **Пример.** Агент продаж видит актуальную цену и наличие; финансовый агент — структуру маржи; публичный консультант — только разрешённую клиентскую информацию.

### R-09.2. Источник истины хранится в одном месте
- **Правило.** Факт (цена, наличие, условие) хранится в одном источнике, а не копируется в пять инструкций; агент получает его через поиск или интеграцию.
- **Почему.** Расхождение версий — главная причина ошибок. При изменении источника обновляется вся система.

### R-09.3. Доступ соответствует действию: три разных полномочия
- **Правило.** Читать данные, предлагать изменение и вносить изменение — три отдельных права. В начале агенту дают чтение и подготовку черновика; право записи — после накопления доказательств стабильности.

### R-09.4. Безопасная лестница выполнения
Прочитать → проанализировать → подготовить → запросить подтверждение → выполнить → записать в журнал.
- **Как применить.** Ступени не пропускаются; на какой ступени агент останавливается без человека, задаётся паспортом (T-1, поле «Ограничения»).

## Глава 10. Проектирование результата

Схема главы (слои стандарта результата): Структура → Поля → Источники → Уверенность → Следующее действие.

### R-10.1. Стандарт результата — главный контракт агента с бизнесом
- **Правило.** Описывайте не только что агент должен знать, но и что он обязан вернуть.
- **Почему.** Иначе ответ может быть умным, но непригодным для следующего действия.

### R-10.2. Элементы стандарта результата
Структура; обязательные поля; допустимый объём; ссылки на источники; уровень уверенности; правила для неизвестных данных.

### R-10.3. Формат зависит от потребителя результата
- **Правило.** Если результат читает человек — важны ясность и краткость. Если его принимает другой агент или система — строгая схема и машиночитаемые статусы.

### R-10.4. Как создать стандарт: сильные примеры плюс негативные
- **Правило.** Соберите несколько сильных человеческих результатов и разберите, что делает их полезными; добавьте негативные примеры: поверхностный анализ, неподтверждённые цифры, пропущенный риск.
- **Почему.** На такой выборке критерии становятся конкретными.

### R-10.5. Формула хорошего результата
- **Правило.** Хороший результат позволяет следующему участнику начать работу без повторного сбора контекста и уточняющих вопросов.
- **Как применить.** Используйте как приёмочный тест любого выхода агента.
